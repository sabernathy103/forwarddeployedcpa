how to read it

Six layers, top to bottom

// delivery

Dashboards the leadership team actually runs on

Custom static apps built with AI in HTML and Python, deployed to Cloudflare Pages in the client's own account. No BI license, no engineering backlog — and each person sees only what they're authorized to see.

// source of truth

A modeled warehouse — every metric defined once

A per-client BigQuery project with dbt models playing the role certified semantic models play in the enterprise stack. Every dashboard inherits the same numbers, and the warehouse ties out to the Xero trial balance daily — a reconciliation, not a hope.

// pipeline

Scheduled, reconciled extracts

Nightly Python extractors on GitHub Actions pull Xero, Gusto, Ramp, and Stripe into the warehouse. Control totals are checked on every run; a broken feed pages the operator, not the client.

// systems of record

Xero and Gusto — one ledger, one payroll, every client

The client owns the subscriptions; you connect as advisor. Standardizing on one ledger is what makes the whole stack repeatable — every bank rule, chart of accounts, and dashboard template transfers to the next client.

// automation band

Transactions coded at the source

Bank feeds with rules, Ramp for cards and AP, Dext or Hubdoc for receipts and supplier bills, Stripe or GoCardless for AR. The goal: the ledger largely writes itself, and the controller reviews exceptions instead of keying entries.

// identity

Cloudflare Access — one identity, end to end

The SMB answer to Entra ID: an access layer you administer that accepts the Google Workspace or Microsoft 365 sign-in the client already uses. One place governs who sees what, across every tool you ship them.

the operating model

Built to be repeated

// ownership

The client owns everything

Xero, Gusto, Ramp, the Cloudflare account, the warehouse project — all in the client's name, billed to the client, with you as the administering advisor. Offboarding is a handover of admin rights, not a data migration.

// isolation

Stamped out per client

No shared database, no client_id column. Each client gets an isolated copy of the stack from a common template. One client's data can never leak into another's dashboard — by architecture.

// the lab

Prototyped on sandboxes first

The whole stack runs in a lab against the Xero Demo Company, Gusto's demo environment, Stripe test mode, and Ramp's sandbox — no certification required. Vendor reviews come later, only when real client data connects.
